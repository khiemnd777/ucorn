# Well Schematic Domain

## Workflow

Read [domain index](../../../docs/well-schematic/README.md), [glossary](../../../docs/well-schematic/glossary.md) and [source audit](../../../docs/well-schematic/source-audit.md). Recheck runtime dispatch before claiming support. For a specific feature, read only its group in [catalog](../../../docs/well-schematic/component-catalog.md).

Identify the selected snapshot (drilling/completion/production/abandonment), wellbore configuration, depth basis/datum and quantities. Separate casing/liner from tubing, support from seal, installed from planned, physical component from context/annotation. Core does not mean implemented. Do not import equipment solely because it appears in a general oilfield drawing.

Produce a component contract with function, fields/units/depth, attachments, symbol/layer/labels, validation, implementation status, fixtures and completion criteria. Identify facts that need operator/manufacturer input. Unknown data stays unknown; no guessed pressure, diameter, barrier status or datum. Follow [sources](../../../docs/well-schematic/sources.md) for verification levels. A drawing expresses supplied configuration and evidence; it does not certify design or safety.

## Result

A scoped domain interpretation, affected catalog IDs, verified definitions and unresolved configuration questions. Proceed with already authorized work; do not manufacture an approval checkpoint for ordinary documentation.
